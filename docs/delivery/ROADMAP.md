Type: explanation/how-to. Revision 3, 2026-09-23. Replaces the API-focused 75-hour release plan. The requested ambition now includes useful voice, cloud continuity and a tutor evidence workflow.

## Outcome and constraints

Deliver LearnSprint's energy-design lesson family as a polished Alexa+ experience simulation, with real AWS-backed coaching and voice, changed-task evidence, useful session restoration and a truthful submission. Follow the [product brief](../product/PRODUCT-BRIEF.md), [acceptance contract](../product/REQUIREMENTS.md) and [judge map](../hackathon/JUDGING-EVIDENCE.md).

Official submission cutoff: **October 24, 2026 at 02:00 Vietnam time** (October 23 noon PDT). Internal target: **October 22 evening Vietnam time**. Keep the review path available through the end of judging. [Official dates and obligations](../hackathon/REQUIREMENTS.md).

Planning assumption: one implementation owner with about **30–32 focused hours per week** over the remaining month. The 130-hour baseline includes 16 hours of contingency. Actual capacity is not yet confirmed; credit does not buy calendar time. At roughly 15 hours/week this full plan will not fit. Report a scope/capacity change explicitly rather than quietly dropping critical behavior.

## What happens first

1. Review the A/B/C constraints and independent reference values; validate the proposed learning job with reachable participants once contact is authorized.
2. Build the smallest A timeline with real outcomes and no required written answer.
3. Resolve one real speech-to-tool path and the hosted transport/authentication contract early.
4. Promote the stable domain contract into persistence, coaching, transfer and reports.

The first [vertical slice](FIRST-SLICE.md) makes the lesson concrete before a cloud stack can distract from it.

## Early feasibility decisions

By September 26: confirm Sonic access/region/language, Node bidirectional SDK behavior and one tool receipt; inspect actual credit/account prerequisites before any necessary paid-plan action. Document unavailability or latency as an implementation risk, not assumed success.

By October 5: voice should perform at least one meaningful action reliably and the coach should reference an actual failed constraint. If not, spend contingency on the cause. If the route remains infeasible, retain a complete text/control simulation and explicitly change the competitive release claims. Native Alexa tooling is not an alternate shortcut; entrant access remains gated.

By October 9: judge hosting/authentication and state isolation must be concrete. Local repository plus video is an allowed fallback, but a live hosted path is our stronger accessibility target. Do not provide the owner's credentials or make a paid account mandatory for the baseline review.

## Scope protection

Preserve: meaningful artifact, energy/power/service consequences, changed-task evaluation, assistance honesty, durable state and a complete accessible workflow. Keep real voice as a high-priority target with an early risk gate.

Cut first: image-to-brief import, translation, extra teacher controls, generated memory summaries, additional lesson families, decorative 3D and extra integrations. P1 work can start only after G4 and without consuming the release/research buffer.

If the remaining core still does not fit, name the specific omitted requirement and revised experience. A smaller working submission can be honest; it cannot be called completion of the full R3 plan.

## Research and release are engineering work

Reserve real time for a fair capable-assistant comparator, novice observation, tutor feedback, accessible/error states and an authentic sub-three-minute demo. Record repeated/failed attempts and real latency. A claim audit must separate proposed features, owner walkthroughs, fixtures, live calls and independent user observations.

No one should have to read a long repository to discover the value. The demo should make the plan's failure, the useful intervention, changed constraints and restored context visible. Service names belong in the technical explanation, not every learner interaction.

## After submission

Preserve the submitted release and report access failures without rewriting the story after the deadline. Maintain the judge path until the evaluation obligation ends. Later development can refine the pack, inspect repeat use and test a tutor-led distribution channel; a bigger curriculum requires content capacity and demand evidence.

The [checklists](CHECKLISTS.md), [risks](RISKS.md) and [status](STATUS.md) are the operational handoff. Planning completion does not mean the product, pilot or submission is complete.
